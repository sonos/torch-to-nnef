    torch_to_nnef.tensor.quant.qtract_ggml

    tract ggml reference block formats (Q8_0, K-quants, IQ formats).

    Like the formats of qtract, the u8 storage holds one quantized code per value and the qscheme holds the block parameters as torch tensors. tract bytes, laid out exactly like llama.cpp block_* structures, are only made when written.

    Quantization ports the ggml reference quantizers in torch: every f32 operation runs in ggml order (sums accumulate sequentially, no fused multiply add), so on CPU the written bytes match llama.cpp reference quantizers built without floating point contraction (-ffp-contract=off; compilers fusing multiply adds give slightly different bytes).

    Warning

    tract (<= 0.23.10) has no matmul or convolution kernel for these formats: only embedding/gathering operations are supported.

    GGMLUnderflowCheck 

    GGMLUnderflowCheck(format_name: str)

    Blocks erased to zeros by f16 scales underflow, over a whole tensor.

    Like llama.cpp and tract quantizers, such blocks are kept as zeros (with a warning) when their weights are negligible against the tensor largest weight (below GGML_UNDERFLOW_REL_TOL of it, the f16 precision): this is a quantization error below what the f16 dequantized tensor can represent. Otherwise the weights are too small as a whole for the format f16 scales. A partial underflow (like Q4_K d rounded to 0 while dmin is not) is not reported: it only drops variations far below the remaining f16 scale, within the quantization error.

    Feed each chunk of blocks to update, then call check.

    QScaleGGMLIQ2S 

    QScaleGGMLIQ2S(d: Tensor, scales: Tensor)

    Bases: QScaleGGMLK

    ggml IQ2_S super-block scheme.

    Per super-block of 256 values: f16 d (n,), and per group of 16 values a 4bit scale scales (n, 16). Each u8 code holds the grid level of its value in bits 1-0 (0, 1 or 2 for magnitudes 8, 25 and 43) and its sign in bit 2 (set for negative), so codes are in {0, 1, 2, 4, 5, 6}. A code dequantizes to (d * (0.5 + scale) * 0.25) * (magnitude * sign).

    Each octet of 8 levels is a point of the ggml kgrid_2bit_1024 grid (its index is looked up when packed). Levels come from a search that the parameters alone do not determine: quantize_blocks runs the deterministic ggml quantizer again and checks it finds these parameters.

    QScaleGGMLK

    Bases: QScheme

    Common base of ggml super-block schemes (K-quants, IQ formats).

    Holds, as torch tensors with a leading super-block dimension (n,), a f16 super-block scale d and per sub-block of SUB_LEN values integer scales, plus format specific parameters (PARAM_NAMES). A code dequantizes in f32 to sub_scales * levels(code) - sub_offsets (tract op order), then is casted.

    Subclass contract
    • SUB_LEN, PARAM_NAMES (constructor tensor arguments, in order), F16_PARAMS (checked for f16 overflow)
    • _settings(): non tensor constructor arguments
    • fit_blocks(x, **settings) -> (scheme, codes): ggml reference quantizer of f32 (n, 256) super-blocks
    • quantize_blocks(x) -> codes: codes of (n, 256) super-blocks with this scheme parameters
    • sub_scales(), optionally sub_offsets() and levels(codes)

    QScaleGGMLK6 

    QScaleGGMLK6(d: Tensor, sc: Tensor)

    Bases: QScaleGGMLK

    ggml Q6_K symmetric super-block scheme.

    Per super-block of 256 values: f16 d (n,), and per sub-block of 16 values i8 scales sc (n, 16). A code q in [0, 63] dequantizes to (d * sc) * (q - 32).

    ggml keeps its make_qx_quants search levels for sub-blocks whose d * sc is 0, and zeros for super-blocks without any scale.

    QScaleGGMLKMin 

    QScaleGGMLKMin(d: Tensor, dmin: Tensor, sc: Tensor, m: Tensor, nmax: int, rmin: float, nstep: int)

    Bases: QScaleGGMLK

    ggml K-quant super-block scheme with mins (Q4_K, Q5_K).

    Per super-block of 256 values: f16 d and dmin (n,), and per sub-block of 32 values 6bit scales sc and mins m (n, 8). A code q in [0, nmax] dequantizes to (d * sc) * q - (dmin * m).

    nmax, rmin and nstep are the format make_qkx2_quants settings: ggml keeps its search levels for sub-blocks whose d * sc is 0.

    QScaleQ8_0 

    QScaleQ8_0(group_size: int, scale: Tensor, n_bits: int, restricted_range: bool = False)

    Bases: QScalePerGroupF16

    Q8_0 f16 scale d per block of 32 (ggml block_q8_0).

    Codes are q + 128 with q in [-127, 127], dequantized in f32 as d * q (like tract), then casted.

    Like llama.cpp quantize_row_q8_0_ref, q = roundf(x / d_f32) with d_f32 = absmax / 127 of the block in f32, before its f16 rounding. quantize_as_u8 recomputes d_f32 from each block of the given tensor and uses it whenever it rounds to the stored f16 scale: this is the case of fp_to_tract_q8_0_with_min_max_calibration (positive scales). Otherwise, the block falls back to the stored f16 scale itself: scales set by an external calibration (GPTQ, clipping, a negative or any other scale than f16(absmax / 127) of the block), or a tensor quantized with scales calibrated on other weights.

    QTensorTractIQ2_S 

    QTensorTractIQ2_S(*args, **kwargs)

    Bases: QTensorTractGGMLK

    Tract data format it serializes to: IQ2_S (ggml block_iq2_s).

    Each super-block of 256 values is stored as 82 bytes (2.5625bpw): f16 d, 32 low grid index bytes then 32 sign bytes (one per octet of 8 values), 8 bytes of 2bit high grid index parts, then sixteen 4bit scales (one per group of 16 values). Each octet is a point of the ggml 1024 entries kgrid_2bit_1024 grid (magnitudes in {8, 25, 43}), value is d * (0.5 + scale) * 0.25 * magnitude * sign.

    Its u8 storage holds one code per value (grid level and sign, see QScaleGGMLIQ2S), grid indices are only looked up when written.

    Quantization ports llama.cpp quantize_row_iq2_s_ref without importance matrix (grid nearest neighbour search with a weighted scale fit, about 2s per 16384 super-blocks on CPU), dequantization matches tract bit exactly.

    Warning

    tract (<= 0.23.10) only supports IQ2_S weights in embedding/gathering operations: there is no matmul or convolution kernel for it yet.

    QTensorTractQ4_K 

    QTensorTractQ4_K(*args, **kwargs)

    Bases: QTensorTractGGMLKMin

    Tract data format it serializes to: Q4_K (ggml block_q4_K).

    Each super-block of 256 values is stored as 144 bytes: f16 d, f16 dmin, 12 bytes of eight 6bit scales and mins (one per sub-block of 32 values), then 256 4bit levels (4.5bpw). Value is d * scale * level - dmin * min.

    Quantization ports llama.cpp quantize_row_q4_K_ref (no importance matrix), dequantization matches tract bit exactly.

    Warning

    tract (<= 0.23.10) only supports Q4_K weights in embedding/gathering operations: there is no matmul or convolution kernel for it yet.

    QTensorTractQ5_K 

    QTensorTractQ5_K(*args, **kwargs)

    Bases: QTensorTractGGMLKMin

    Tract data format it serializes to: Q5_K (ggml block_q5_K).

    Each super-block of 256 values is stored as 176 bytes: f16 d, f16 dmin, 12 bytes of eight 6bit scales and mins (one per sub-block of 32 values), 32 bytes of level high bits, then 256 low 4bit levels (5.5bpw). Value is d * scale * level - dmin * min with 5bit levels.

    Quantization ports llama.cpp quantize_row_q5_K_ref (no importance matrix), dequantization matches tract bit exactly.

    Warning

    tract (<= 0.23.10) only supports Q5_K weights in embedding/gathering operations: there is no matmul or convolution kernel for it yet.

    QTensorTractQ6_K 

    QTensorTractQ6_K(*args, **kwargs)

    Bases: QTensorTractGGMLK

    Tract data format it serializes to: Q6_K (ggml block_q6_K).

    Each super-block of 256 values is stored as 210 bytes: 128 bytes of low 4 bits and 64 bytes of high 2 bits of 256 6bit levels, sixteen i8 scales (one per sub-block of 16 values), then f16 d (6.5625bpw). It is symmetric: value is d * scale * (level - 32).

    Quantization ports llama.cpp quantize_row_q6_K_ref (no importance matrix), dequantization matches tract bit exactly.

    Warning

    tract (<= 0.23.10) only supports Q6_K weights in embedding/gathering operations: there is no matmul or convolution kernel for it yet.

    QTensorTractQ8_0 

    QTensorTractQ8_0(*args, **kwargs)

    Bases: QTensorTractScalePerGroupF16

    Tract data format it serializes to: Q8_0 (ggml block_q8_0).

    Each group of 32 values is stored as 34 bytes: f16 scale d, then 32 int8 (8.5bpw). Value is d * q.

    Use fp_to_tract_q8_0_with_min_max_calibration to construct it: quantization matches llama.cpp quantize_row_q8_0_ref bytes, dequantization matches tract bit exactly. External calibrations provide their scales with a QScaleQ8_0.

    Warning

    tract (<= 0.23.10) only supports Q8_0 weights in embedding/gathering operations: there is no matmul or convolution kernel for it yet. Export requires tract >= 0.23.10; older targets warn and are rejected.

    ggml_sqrt 

    ggml_sqrt(arr: Tensor) -> torch.Tensor

    Correctly rounded f32 square root (IEEE sqrtf), on every platform.

    torch.sqrt is not: x86 builds compute it with MKL vector math, accurate to about 1 ulp only, and its result depends on the CPU model. The f32 rounding of the f64 root is fixed up with exact f64 checks: the midpoint of two consecutive f32 has at most 25 significant bits, so its f64 square is exact (and never equals a f32, so there are no ties).
